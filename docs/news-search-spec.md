## 0. 已确认决策记录

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 页面定位 | 一级菜单「资讯」（route `/news`）的落地页即搜索页（search-first）；后续公告列表、CLS 日报浏览作为该菜单下的补充 Tab，**不做**两个重叠的一级入口 |
| D2 | 「加为持仓」不做 | 搜索卡片不提供任何写账本动作，与 ledger 域完全解耦。卡片操作区仅保留【订阅公告】与【追问 AI】两个动作，均为现成能力。未来若需要，以「跳转持仓页并预选标的」的解耦方式另行评估 |
| D3 | 意图分流语义 | 三个 Filter 约束的是**检索范围**（公告库 / CLS 库 / 双库+LLM 综合），不是猜测用户意图；输入框的"股票/关键词"形态由前端确定性检测（6 位数字码、Smartbox 消歧）自动识别 |
| D4 | 持仓数据注入方式 | 持仓数据在本地（E2EE，服务端只有密文），RAG 服务不可能知道用户持仓。「持仓公告」范围由**前端把当前持仓的 6 位代码列表作为查询参数**传给检索接口（隐私友好、后端无状态） |
| D5 | 结果状态层级 | 搜索结果必须落 `store/slices/searchSlice.ts`（R2 护栏：Copilot 区块快照严禁读取视图局部 useState/闭包，必须经 getState() 同源读取），不得存视图局部状态 |
| D6 | 复用优先 | 订阅动作复用已上线的 `announcementSlice`（与交易卡片共享订阅态）；追问 AI 复用 Copilot `focusBlock` 区块聚焦机制（`BlockFocusButton` 同款）；股票消歧复用 `StockAutocomplete`（Smartbox）；行情展示复用 `useLiveQuotes` |
| D7 | 分期与 mock | P0 前端骨架以 mock 数据先行（`searchService` 内置 mock 提供者，常量开关切换），交互全部跑通；P1 接真实公告检索；P2 接 CLS 检索与综合摘要。切真实接口前搜索页要求登录，mock 模式不强制 |
| D8 | 三不原则 | 不说废话（搜索框 + 预置 Prompt 引导，永不弹空白 Chat）；不做长文展现（结果只展示提炼好的 2~3 句结构化摘要，原文点击再展开）；不出单向死胡同（每个卡片都有「订阅」或「追问 AI」下一步动作） |
| D9 | 综合摘要延迟管理 | 「AI 智能综合」是秒级到十秒级操作，与即时检索体验分离：显式"生成中"状态 + 可流式返回（若后端支持 SSE），不做假加载 |
| D10 | 未登录态 | 真实检索接口需登录会话（WebConfig 拦截）；未登录时页面展示引导登录空态（打开既有 AuthModal），不做游客检索 |

## 1. 背景与目标

### 1.1 背景

- 公告订阅闭环已建成：短线/中长期交易卡片可一键订阅（`AnnouncementSubscribeButton`），后端 CNINFO 爬虫已将 2023 至今的公告摘要渐进入库。
- 但**消费面缺失**：订阅之后用户没有地方看公告摘要，也没有任何检索入口。资讯数据（公告 + 后续财联社早晚报）需要一个统一的信息消费界面。
- 金融信息检索的典型痛点：用户不知道怎么问（冷启动）、搜索结果是无结构长文（阅读成本高）、搜到结果后没有下一步动作（死胡同）。

### 1.2 目标

1. 提供一个**搜索优先**的资讯消费页，让用户以最低成本查到"我的持仓有什么动静"与"市场发生了什么"。
2. 检索结果一律**结构化卡片**呈现：大模型/后端提炼的 2~3 句摘要 + 确定性元信息（股票、日期、来源）。
3. 每个结果卡片都通向下一步动作：订阅该股票公告，或把该条结果作为上下文唤起 AI Copilot 深入追问。
4. 为后续「财联社日报」数据接入预留完整的界面与契约位置（P2 无需改版）。

## 3. 功能需求

### F1 确定性意图分流（Intent Filters）

搜索框下方提供三个语义 Filter 标签（单选，默认选中「持仓公告」）：

| Filter | 检索范围 | 排序规则 | 持仓限定 |
|--------|----------|----------|----------|
| 📌 持仓公告（默认） | 巨潮公告摘要向量库 | 股票名称 + 公告日期倒序 | **默认限定当前持仓**的 6 位代码集合（D4） |
| 📰 财联社早晚报 | CLS 早晚报向量库 | 发布日期倒序 | 不限定；提供日期范围筛选（近 7 天 / 近 30 天 / 自定义，P2） |
| 🤖 AI 智能综合 | 双库同时检索 + LLM 串联摘要 | 无列表，输出综合摘要段 + 引用来源 | 跟随输入形态（见下） |

> **语料覆盖边界（v1.2）**：公告语料为订阅驱动（后端仅采集被订阅标的，2023 至今），检索召回范围 = 全体用户订阅标的的**并集**，非全市场。持仓股票若从未被任何用户订阅，其公告不在语料内（A2 场景可能假阴性）——空结果态需区分「命中 0 条」与「疑似未收录」，对后者给「订阅该股后可检索」引导（复用订阅闭环，不自动扩采）。

**确定性形态检测（优先级高于 Filter）**：
- 输入命中 6 位数字码（`/^\d{6}$/`）或经 Smartbox 消歧选中具体股票 → 无论当前 Filter 是什么，顶部先出「股票确定性档案卡」（见 F2 场景 1）；Filter 仅决定档案卡之下的检索范围。
- 其他输入 → 按事件关键词走当前 Filter 的范围（F2 场景 2）。
- 「持仓公告」范围下，若本地无进行中持仓 → 结果区展示引导空态（「当前无持仓，去添加持仓或切换范围」），不发请求。

**交互要求**：
- Filter 切换后**不自动重新搜索**（避免误触发 LLM 消耗），已有关键词时搜索框获得焦点或用户点搜索才重新查询；输入为空时切换 Filter 仅更新空态/预置模板。
- 「AI 智能综合」按钮点击后立即进入显式「生成中」态（D9），生成期间允许浏览已检索库结果（若前端先行展示了双库列表）或展示骨架屏。

### F2 结构化结果卡片

#### 场景 1：股票确定性档案卡（输入为代码/名称时置顶展示）

- 卡头：`🟢 600745 闻泰科技`——圆点颜色跟随实时涨跌（复用 `useLiveQuotes`，红涨绿跌），右侧展示现价与涨跌幅（有行情时）。
- 区块一【最新公告摘要】：最新 1~3 条公告的日期 + 提炼摘要（来自检索接口，标注日期如 `(2026-09-08)`）。
- 区块二【财联社提及】：近 7 天提及次数 + 最近几条快讯摘要（P2，CLS 数据就绪前隐藏该区块）。
- 操作区：【🔔 订阅公告】（订阅态与交易卡片同源，已订阅显示为已订阅可取消）+【💬 唤醒 AI 深入追问该股】。
- **明确不做**：「加为持仓」（D2）。
- 数据获取：优先走后端聚合接口（`GET /api/search/stock-profile`，见接口文档）；后端未就绪时前端组合降级（公告检索接口按股票过滤 + 订阅态本地镜像）。
- **未知股票降级**：stock-profile 返回 400（stockId 非法，如退市/无公告覆盖的代码）时，**静默降级为以该代码作关键词的普通检索**（结果列表照常展示），不弹错误 toast（后端评审补充，覆盖 A1 未描述的边界）。

#### 场景 2：事件/关键词聚合（输入为概念/事件关键词时）

- 列表头：「📄 匹配到 N 条相关公告摘要」。
- 每条命中一行式卡片：`股票代码 股票名称 (公告日期)：2~3 句提炼摘要`，命中关键词高亮。
- 点击卡片展开原文摘要全文（P1 为摘要全文；公告原文链接跳转巨潮，P2 评估内嵌详情）。
- CLS 范围下的结果卡片：日期 + 早报/晚报标识 + 提炼摘要 + 提及股票的 chips；点击股票 chip 等价于以该股票发起档案卡查询（P2）。
- 每条卡片操作区：【🔔 订阅公告】（公告类卡片）/【💬 针对此条追问 AI】。

### F3 预置提问模板（Search Prompts）

搜索框为空或获得焦点时，展示两组合高频模板（点击即填充并发起查询，用户零输入成本）：

| 分组 | 模板 | 实际执行的查询 |
|------|------|----------------|
| 持仓风险类 | 近 30 天有哪些持仓股票发布了减持或质押公告？ | scope=公告库 + stockCodes=当前持仓 + dateRange=近30天 + query=减持 质押 |
| 持仓风险类 | 查一下我的持仓里有没有涉及「对赌协议」的风险公告？ | scope=公告库 + stockCodes=当前持仓 + query=对赌协议 |
| 宏观与快讯类 | 搜索今天的财联社早报核心提炼 | scope=CLS 库 + dateRange=今天 + query=早报 核心提炼（P2） |
| 宏观与快讯类 | 本周财联社电报里提及最多的板块是什么？ | scope=综合 + query=本周板块 提及统计（P2） |

- 模板清单前端静态维护（`utils/` 常量），P2 评估是否改为后端下发热榜。
- 持仓类模板在无持仓时置灰 + 提示文案。

### F4 搜索 → AI Copilot 联动（Search-to-Copilot）

- 每个结果卡片下方有【💬 针对此条追问 AI】；档案卡为【💬 唤醒 AI 深入追问该股】。
- 点击后**不跳转页面**：直接展开全局 Copilot 浮窗并聚焦该卡片的区块上下文（复用 `focusBlock(scopeId, blockId)` 机制）。
- 卡片注册的上下文 = 该条结果的结构化摘要全文 + 确定性元信息（股票/日期/来源）+ 建议追问（如「帮我算算这条公告提到的减持比例对股价影响大吗？」）。
- 上下文内容从 `searchSlice` 读取（D5），查询切换后旧结果卡片的注册随组件卸载自动注销（沿用现有 usePageContext 挂载/卸载语义）。

## 4. 界面与交互规范

### 4.1 页面状态机

| 状态 | 触发 | 展示 |
|------|------|------|
| 初始态 | 进入页面 / 清空输入 | 搜索框（含占位示例文案）+ 三 Filter + 预置模板两分组 |
| 检索中 | 发起查询 | 骨架屏（3~5 张卡片占位）；综合摘要另有独立生成中态 |
| 结果态 | 检索成功 | 档案卡（若股票形态）+ 结果卡片列表；顶部显示结果数与所用范围 |
| 空结果 | 命中 0 条 | 「未找到相关内容」+ 建议切换范围/换关键词 + 预置模板入口 |
| 失败态 | 网络/服务错误 | 错误文案（信封 message 直出或网络异常文案）+ 重试按钮 |
| 未登录 | 真实接口 401 / 本地无会话 | 引导登录空态（「登录后可检索公告与快讯」+ 登录按钮，打开既有 AuthModal） |
| 生成中 | 综合摘要请求已发出 | 显式进度提示（「AI 正在综合两个库的信息…」），支持流式渐进渲染（若 SSE） |

### 4.2 反馈约定

- 后端业务错误（信封 400，如参数非法/限流）的 `message` 为用户可读中文，直接 toast/内联展示，前端不二次包装。
- 限流（信封 429）展示「请求过于频繁，请 N 秒后重试」（`retryAfterSeconds`）。
- 检索历史不做本地持久化（一期）；刷新即回初始态。
